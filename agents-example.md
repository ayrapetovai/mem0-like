# Проект: домашний Kubernetes-node на X79/C602 mATX

## Память проекта (обязательна при работе по сборке)

Поисковая память проекта лежит в `mem0-like\memory\*.md` — по файлу на тему: `hardware.md`
(сборка: CPU, плата, RAM, кулер, короб, БП, корпус, fan-control), `game-design.md` (Strata:
механики, бой, сюжет, квесты, NPC, канон, режимы, сеть), `flow.md` (поток решений по проекту и
окружению). Индекс — `mem0-like\search.py` (SQLite FTS5 + векторы multilingual MiniLM-L12-v2),
поиск идёт по всем темам; `--topic hardware` / `--topic game-design` сужает результат.

Запуск поиска:

    mem0-like\.venv\Scripts\python.exe mem0-like\search.py "запрос" -k 5

Другие режимы: `--no-embed` (точный поиск без векторов), `--add "текст" --topic flow` (добавить
строку в файл темы), `--reindex`, `--stats` (число документов и разбивка по темам). Индекс
`mem0-like\memory.db` перестраивается сам при изменении файлов в `mem0-like\memory\` — только
изменённая тема. Окружение после клонирования собирает `python mem0-like\init.py` (venv, пакет,
модель, индекс); диагностика без правок — `python mem0-like\init.py --check`.

### Когда вызывать поиск

Перед ответом про цифры, совместимость или решения по сборке — CPU, плата, RAM, кулер,
короб/воздушный поток, шум, БП, корпус и крепления, fan-control, сеть, диск, троттлинг — искать
в `--topic hardware`. Перед ответом про Strata (бой, сюжет, квесты, NPC, канон, режимы, сеть,
модель для генерации) — искать в `--topic game-design`. Не пересказывать числа и решения по
памяти: сначала поиск, потом ответ с `#topic:n` найденных строк.

### Когда писать в память

Новое решение, подтверждённая карточка товара, результат измерения или проверка после сборки —
сразу одна строка в нужной теме: `--add "текст" --topic hardware` (сборка), `--topic game-design`
(Strata), `--topic flow` (процесс проекта); или правкой файла `mem0-like\memory\<тема>.md`.
Формат: один bullet = один факт, `##` = раздел. Точные единицы и модель сохраняются текстом,
не пересказом.
