# mem0-like — память проекта

Проект называется **mem0-like**, папка `mem0-like\` в корне workspace. Имя подчёркивает идею:
автопамять как в mem0, но без сервера, без LLM-вызовов для извлечения фактов и без облака —
факты пишутся текстом, поиск локальный.

## Основная идея

Это маленький локальный «мозг» проекта: один текстовый файл с фактами + скрипт гибридного
поиска по нему. Нужен для того, чтобы AI в **новой** сессии не терял цифры и решения,
накопленные в предыдущих: контекст сессии сжимается и забывает детали, а файлы остаются.

Работает без сервера, без сети (кроме первичной скачки модели), без базы данных на диске
кроме одного SQLite-файла. Два индекса на одном тексте:

- **FTS5 / BM25** — точные токены: числа, модели, артикулы, единицы («+12V», «1866», «SNK-P0048PW»).
- **Векторы (эмбеддинги)** — смысл и синонимы («почему отказались от башенного кулера» найдёт
  запись, где слово «башенный» не написано прямо).

Рейтинг объединяется через RRF: `score = Σ 1/(60 + rank)` в каждом из двух списков, поэтому
документ, который нашли оба индекса, поднимается выше.

### Как AI узнаёт об этом в новой сессии

Не из этой папки, а из **`AGENTS.md` в корне workspace** (`C:\Users\USERNAME\Documents\Strata\Workspace\AGENTS.md`).
Приложение загружает его как проектные инструкции в начале каждой сессии этого workspace, и там
написано: где лежит память, какой командой искать, когда искать и когда писать.

**Как создать `AGENTS.md`** (если его нет — например, проект переехал в другую папку):

1. Создать файл `AGENTS.md` в корне workspace (не в `mem0-like\`).
2. Записать в него: путь к памяти, команду поиска, триггеры «когда искать» и «когда писать»,
   ограничения окружения. Кратко, без самих цифр — цифры живут в `memory.md`.
3. Проверить: новая сессия в этом workspace должна упомянуть эти инструкции сама.

Корневой `AGENTS.md` — рабочий файл: его загружает приложение в начале сессии. Копия для
контроля версий — `mem0-like/agents-example.md`. Она намеренно названа не `agents.md`: Windows не
различает регистр имени, и приложение прочитало бы `mem0-like\agents.md` как `mem0-like\AGENTS.md` —
инструкции инжектировались бы дважды (корневой файл + подпапка). Правки делать в корневом
`AGENTS.md`, затем копировать в `agents-example.md` (или наоборот), иначе репозиторий расходится
с тем, что реально читается в сессии. Проверка совпадения: `Get-FileHash AGENTS.md`,
`Get-FileHash mem0-like\agents-example.md`.

Минимальный шаблон:

```markdown
# Проект: <название>

## Память проекта
В workspace есть поисковая память: `mem0-like\memory.md` + `mem0-like\search.py` (SQLite FTS5 + векторы).
Запуск: `mem0-like\.venv\Scripts\python.exe mem0-like\search.py "запрос" -k 5`
Режимы: `--no-embed`, `--add "текст"`, `--reindex`, `--stats`.
После клонирования окружение (venv, модель, индекс) собирает `python mem0-like\init.py`.

### Когда вызывать поиск
Перед ответом про цифры, совместимость и решения по <тема проекта>. Сначала поиск, потом ответ.

### Когда писать в память
Новое решение, подтверждённая карточка, результат измерения — одна строка через `--add`.

## Ограничения окружения
Windows + PowerShell; Python 3.12; <что отсутствует>. Рабочая директория: <путь>.
```

Если `AGENTS.md` не подхватывается (другое приложение или другая папка), единственный
гарантированный вариант — одна строка в первом сообщении: «используй память в `mem0-like\`».

## Что лежит в папке

| Файл | Размер | Что это | Зачем |
|---|---|---|---|
| `memory.md` | ~6 КБ | **источник истины**: документы по одному факту, сгруппированы по `##` | правится руками или через `--add`; только он читается при индексации |
| `search.py` | ~7 КБ | скрипт: чтение `memory.md`, индексация, гибридный поиск, вывод | точка входа поиска |
| `init.py` | ~7 КБ | диагностика и восстановление окружения: venv, `fastembed`, модель, `memory.db` | точка входа после клонирования |
| `memory.db` | ~0.6 МБ | SQLite-индекс: `doc` (тексты), `fts` (FTS5-таблица), `vec` (векторы JSON), `meta` (хэш источника) | производный; можно удалить — перестроится сам |
| `.models` | ~240 МБ | кэш модели эмбеддингов `Qdrant/paraphrase-multilingual-MiniLM-L12-v2-onnx-Q` (ONNX, квант Q) | веса универсальные, не зависят от `memory.md`; нужны для офлайн-работы |
| `.venv` | ~173 МБ | изолированное Python-окружение: launcher + `fastembed`, `onnxruntime`, `numpy`, `tokenizers`, `huggingface_hub`, `pip` | чтобы поиск не зависел от системного Python |
| `README.md` | — | этот файл | описание для AI и человека: идея, использование, доработка |

Ваш текст находится **только** в `memory.md`. `memory.db` — производный индекс, `.models` и `.venv` —
инструмент. `README.md` в индекс не попадает: скрипт читает исключительно `memory.md`.

## После клонирования репозитория

В git лежат только текст и код: `memory.md`, `search.py`, `init.py`, `README.md`,
`agents-example.md`, `.gitignore`. Скачанное и производное (`memory.db`, `.models`, `.venv`)
не клонируется — сразу после `git clone` поиск не работает. Инициализация одна команда:

```
python mem0-like\init.py
```

Она проверяет всё необходимое и доводит до рабочего состояния:

| Проверяет | Что делает, если не так |
|---|---|
| `memory.md`, `search.py`, `.git` | сообщает «нет» — без них память не работает |
| `.venv` | `python -m venv .venv` (интерпретатор берётся из `pyvenv.cfg` или из системного Python) |
| пакет `fastembed` | `pip install` через кэш `.pip-cache`, кэш удаляется после установки |
| `.models` (модель) | проверяет наличие `model_optimized.onnx` / `tokenizer.json` / `config.json`, размеры и читаемость JSON; при отсутствии или порче удаляет кэш репозитория и скачивает заново, затем эмбеддинит тестовую строку |
| `memory.db` | перестроение из `memory.md` (тот же `search.rebuild`, включая миграцию FTS5); если хэш источника совпадает — ничего не делается |

Флаги:

```
python mem0-like\init.py --check   # только диагностика: ничего не создаёт, не скачивает, не правит
python mem0-like\init.py --force   # перекачать модель и перестроить индекс заново
```

Запуск из корня workspace (`python mem0-like\init.py`) или из папки памяти (`python init.py`) —
оба работают, пути внутри скрипта абсолютные относительно самого файла. Код выхода: `0` — всё
готово, `1` — есть `FAIL`, см. строки выше. Идемпотентен: повторный запуск при уже собранном
окружении ничего лишнего не делает и не трогает индекс.

Требуется сеть только когда чего-то не хватает (venv, пакет, модель). Если сеть недоступна,
`--check` покажет отсутствующее, а точный поиск продолжит работать после `--no-embed`.

Проверено на этом компьютере: полный запуск при пустом `.models` скачивает модель и эмбеддинги
работают; удалённый `memory.db` перестраивается из `memory.md`; повреждённый `config.json`
опознаётся как «модель повреждена» и лечится перекачиванием.

## Как это работает (поток)

1. `read_entries()` — каждая строка `- ...` в `memory.md` становится отдельным документом
   вида `раздел :: текст`, где раздел берётся из ближайшего заголовка `##`.
2. `rebuild()` — считает SHA-256 от всех документов; если он совпадает с `meta.docs_hash`,
   индекс не трогается. Иначе: очищение `doc`/`fts`/`vec`, вставка текстов, затем векторы.
3. `fts_search()` — запрос разбивается на токены (`[A-Za-zА-Яа-яЁё0-9]+`), собирается
   `"токен" OR "токен"` и выполняется `fts MATCH ... ORDER BY bm25(fts)`.
4. `vec_search()` — запрос эмбеддинится той же моделью, косинусное расстояние против каждого
   сохранённого вектора, топ-20.
5. `search()` — RRF по двум спискам рангов, топ-`k`, вывод `[score] #id раздел :: текст`
   (длина строки в выводе ограничена 240 символами).
6. `--no-embed` — векторы не используются; вместо BM25 простой подсчёт вхождения токенов
   (`fts_only_search`). Полезно, чтобы проверить, что найдено бы только по точным словам.

Нумерация документов (`#id`) = порядок в `memory.md`, поэтому id меняется при правках выше по
файлу; ссылаться в ответах лучше на текст, а не на id.

## Как пользоваться

Команды (из корня workspace, PowerShell):

```powershell
mem0-like\.venv\Scripts\python.exe mem0-like\search.py "ток по +12V" -k 5
mem0-like\.venv\Scripts\python.exe mem0-like\search.py "почему отказались от башенного кулера"
mem0-like\.venv\Scripts\python.exe mem0-like\search.py "сколько воздуха нужно прогнать через рёбра"
mem0-like\.venv\Scripts\python.exe mem0-like\search.py "Fan Error" -k 3 --no-embed
mem0-like\.venv\Scripts\python.exe mem0-like\search.py --stats
mem0-like\.venv\Scripts\python.exe mem0-like\search.py --add "Новое решение: ..."
mem0-like\.venv\Scripts\python.exe mem0-like\search.py --reindex
```

Правило применения: сначала поиск, потом ответ. Если поиск ничего не нашёл — это тоже
информация («этого решения ещё нет в памяти»), и её стоит записать после обсуждения.

## Формат `memory.md`

- Один bullet `- ` = один факт. Не смешивать несколько фактов в одной строке: поиск выдаёт
  строку целиком, и длинная строка размывает результат.
- `## Заголовок` = раздел; он попадает в текст документа и помогает фильтровать («Диск»,
  «Кулер и короб», «Управление вентилятором», «Не проверено», «Поток решений»).
- Точные единицы и модели пишутся текстом: «445 см²», «≥ 15 A», «PC3-14900R», «SNK-P0048PW».
  Векторы и извлекатели их искажают, FTS — нет.
- Раздел `## Не проверено` — то, что не подтверждено источником; ответы по этим пунктам
  должны помечаться как оценка.
- Раздел `## Поток решений` — куда `--add` дописывает новые записи.
- Правки руками безопаснее, чем `--add` из PowerShell: кириллица и кавычки в shell могут
  испортить строку (см. «Подводные камни»).

## Как обновить

- Правка `memory.md` → следующий любой вызов сам перестроит индекс (сравнение хэша).
- `--add "текст"` → append под `## Поток решений` + переиндексация.
- `--reindex` → принудительное перестроение (например, после правки модели или формата).
- `--stats` → число документов, актуален ли индекс, включены ли векторы, имя модели.
- Очистка: удалить `memory.db` — при следующем вызове индекс создаётся заново.
- Клонирование или перенос проекта: скопировать `memory.md` + `search.py` + `init.py` (+ этот
  README) и запустить `python mem0-like\init.py` — он соберёт `.venv`, `.models` и `memory.db`.
  Вручную те же шаги: `python -m venv mem0-like\.venv`,
  `mem0-like\.venv\Scripts\python.exe -m pip install fastembed`, первый поиск скачает модель.
  `.venv` и `.models` между ОС и архитектурами не переносится — на новом месте их собирает
  `init.py`, а не копирование. Создать там `AGENTS.md` (шаблон выше).

## Как доработать (что стоит добавить при росте памяти)

- **Разделы как фильтр**: добавить в FTS отдельную колонку `section` и искать
  `fts MATCH ? AND section = ...` — сейчас раздел внутри текста.
- **Дедупликация**: перед `--add` сравнивать новые записи с результатами поиска и не писать
  дубликаты; при противоречии — править старый документ, а не добавлять новый.
- **Метаданные**: дата, источник (URL карточки), статус («подтверждено»/«оценка»); вывод
  должен показывать источник, чтобы ответ не выдавал оценку как факт.
- **Rerank**: после RRF пропустить топ-10 через cross-encoder — заметно точнее на коротких
  документах, но медленнее.
- **Другая модель**: заменить `MODEL_NAME` (например `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
  на более крупную multilingual) и сделать `--reindex`; `.models` для неё скачается отдельно.
- **Хранилище векторов**: при сотнях документов cosine-перебор в Python медленный —
  заменить на `sqlite-vec` или отдельный ANN-индекс.
- **MCP-обёртка**: тот же скрипт как MCP-сервер (`search`/`add`) — тогда вызовы видны как
  инструменты, а не как shell. Сейчас не настроено: конфигурация MCP в этом приложении не найдена.
- **Авто-извлечение (mem0-подобное)**: LLM выжимает из диалога факты и пишет их в `memory.md`.
  Для инженерных чисел это хуже ручного лога: извлечение перефразирует и теряет единицы,
  поэтому включается только для решений и текстовых выводов, не для цифр.

## Ограничения

- Память привязана к одному workspace: `AGENTS.md` загружается только для него.
- Автоматического съёма диалога нет: пишется только то, что явно записано.
- Индекс строится только из `memory.md`; другие файлы не ищутся.
- Векторы считаются на уровне строки-документа, не длинного раздела: очень длинные абзацы
  размывают смысл — дробить на bullets.
- SQLite и FTS5 из стандартной библиотеки Python; отдельного сервера нет.

## Подводные камни (уже проверены)

- **Кодировка вывода**: PowerShell по умолчанию cp1251 → `UnicodeEncodeError` на символах вроде
  `≈`. Скрипт сам ставит `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`.
- **FTS5 vs обычная таблица**: если `fts` создана как `CREATE TABLE fts(text)`, `bm25()` падает.
  В `connect()` есть миграция: если в схеме нет `fts5` — таблица пересоздаётся как virtual.
- **float32**: эмбеддинги из fastembed — `numpy.float32`, `json.dumps` на них падает;
  конвертация в `float` в `embed()`.
- **Имя модели**: `paraphrase-multilingual-MiniLM-L12-v2` (L12), не `L128` — иначе ImportError.
- **PowerShell и `--add`**: кавычки и обратные слэши в Cyrillic-пути могут испортить запись;
  после `--add` проверьте строку в `memory.md` или правьте файл напрямую.
- **`pyvenv.cfg`**: строка `command` записана с битой кодировкой (путь с кириллицей), на работу
  не влияет — пути читаются через `Scripts\python.exe`.
- **Первый запуск**: требует интернета для скачки модели (~224 МБ); офлайн работает, пока
  `.models` на месте.

## Быстрая диагностика

| Симптом | Проверка |
|---|---|
| Клонировали репозиторий, окружения нет | `python mem0-like\init.py` (нужен интернет: venv + пакет + модель + индекс) |
| Не понятно, что отсутствует или повреждено | `python mem0-like\init.py --check` — список OK/FAIL без правок |
| «совпадений нет» на очевидный запрос | `--no-embed` с точным токеном; если FTS нашёл, а гибрид нет — проблема в векторах |
| Индекс не обновился после правки | `--stats` (строка «индекс: актуален/перестроен»), затем `--reindex` |
| Векторы выключены | `--stats` → «векторы: 0»; проверить `.venv` и `.models` |
| Ошибка BM25 | удалить `memory.db`, вызвать любой запрос (миграция пересоздаст `fts`) |
| Модель не скачивается или грузится с ошибкой | `python mem0-like\init.py --force` (перекачивает `.models`); если сети нет — оставить `.models` целым и работать через `--no-embed` |
